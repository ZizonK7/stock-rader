# papers/ — 논문·심사·결정 (시범 중)

## 역할
기록을 보고 '이런 것 같다'는 주장을 한 편의 글(논문)로 쓰고, 다른 에이전트(심사자, 다른 모델)가 기록과 계산으로 비판하고, 학회장(메인 대화 세션)이 받아들일지 정하는 곳이다. 2026-11-25 사용자가 시범으로 해 보자고 했다 — 양식과 이 폴더를 계속 쓸지는 사용자가 첫 결과를 보고 정한다.

한 편마다 폴더 하나(`P-0001/` …):

| 파일 | 누가 | 무엇 |
|---|---|---|
| `call.md` | 학회장 | 투고 요청서(질문·문제 의식·재료·규칙·낼 것·하지 않을 것·심사에서 볼 것) — 받은 그대로 |
| `paper.md` | 저자 | 논문. 요청서가 정한 절 번호·이름을 그대로 쓴다 |
| `evidence.py` | 저자 | 논문의 모든 숫자를 기록·시세에서 다시 계산해 찍는 스크립트(읽기만, 표준 출력만) |
| `review-*.md` | 심사자 | 심사서(있으면). 심사자는 다른 파일을 고치지 않는다 |
| `decision.md` | 학회장 | 결정(있으면): 채택 / 고쳐서 다시 / 거절과 까닭 |

## 규칙
- 조건은 판단하던 때 잴 수 있던 것만 쓴다. 값의 시각(known_through·as_of·run)으로 확인하고, 판단 뒤 값이 섞이면 그 후보는 버린다.
- 맞은 날·잃지 않은 날까지 모두 대 본다. 같은 사건·겹치는 기간은 한 건으로 묶은 수(독립 사례)를 같이 적는다(lessons.toml L09).
- 해 본 후보는 버린 것까지 모두 적는다.
- 과거 사례에 맞는 것은 '채택 시험'이지 성적이 아니다. 성적은 세운 뒤의 날들로만 센다. '검증됨'이라고 쓰지 않는다.
- 숫자는 `evidence.py` 출력에서만 가져오고, 문턱마다 정한 까닭과 다시 볼 기준을 적는다.
- 지난 날의 조사 조건 값을 지금 웹 검색으로 새로 만들지 않고, 기록된 조사 답의 글을 읽어 예/아니오를 새로 매기지 않는다(결과를 아는 채 읽게 된다). 새 조건은 숫자 문턱을 먼저 적고 기록된 숫자에서 코드가 값을 꺼낸다.
- 공개 저장소다: 비밀값·개인 정보·기사 본문을 두지 않는다.

## 다른 폴더와의 관계
- `records/`·`data/prices/`·`knowledge.toml`·`lessons.toml`은 **읽기만** 한다. `evidence.py`는 `market/`의 읽기 함수(`prices.load`·`pieces.read`·`config`)를 불러 매일 실행과 같은 잣대로 계산한다 — `market/`을 고치지 않는다.
- 논리집(`knowledge.toml`)에 조각을 세우는 일은 심사 뒤 학회장이 결정하고 나서 따로 한다. 이 폴더에서는 하지 않는다.
- 예약 실행은 이 폴더를 읽지 않는다(루트 CLAUDE.md에 이 폴더를 적는 것도 채택이 정해진 뒤).

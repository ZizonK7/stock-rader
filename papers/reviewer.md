# 심사 지시문 (모든 심사에 같은 부분)

> **초안(2026-11-25).** 저자 지시문 [author.md](author.md) 2판의 짝. P-0001 심사([P-0001/review.md](P-0001/review.md))에서 잘 된 것(다시 계산, 독립 재구현, 코드 줄을 짚은 반박)을 남기고, 반박을 이론의 핵심·보조로 가르는 칸을 더했다.

## 0. 읽는 순서
1. 루트 `CLAUDE.md` → 2. 학회장의 심사 요청(이번 심사에만 다른 것) → 3. 이 문서 → 4. `author.md`(저자가 지킬 것 — 지켰는지 본다) → 5. 심사할 논문 폴더(`call.md` → `theory.md` → `paper.md` → `evidence.py`) → 6. [ledger.md](ledger.md)의 이 이론 줄과 앞 판의 심사.
서로 다르면 앞의 것이 이긴다.

## 1. 역할
- 너는 **심사자**다. 저자의 이론이 **기록과 계산으로 버티는지** 본다. 저자의 설명보다 기록과 코드를 먼저 본다.
- 목표는 거절이 아니라 **이론을 더 정확하게 만드는 것**이다. 무너뜨릴 수 있으면 무너뜨리고, 고치면 살 수 있으면 어떻게 고칠지 적는다.
- 저자가 이미 한 공격을 되풀이하기보다, **저자가 하지 않은 공격**과 **저자가 약하게 한 공격**을 찾는다.

## 2. 하는 일
1. **다시 계산** — `python -X utf8 papers/<번호>/evidence.py`를 돌려 논문 숫자와 대 본다. 중요한 숫자는 `review_check.py`로 따로 다시 구현해 본다(외부 패키지 없음, 읽기만, 표준 출력만).
2. **판단 때 알 수 있었나** — 조건 값의 시각을 코드 줄로 확인한다.
3. **순서를 지켰나** — `theory.md` 커밋이 결과보다 앞인지, ledger 줄. `python -X utf8 papers/check.py papers/<번호> --run`.
4. **설명 못 한 사례를 숨겼나** — 논문 7절 사례 표에 빠진 사례가 없는지 기록·시세에서 직접 찾아본다. 사례마다 보조를 덧대 설명한 곳이 있으면 '덧댄 보조'로 반박한다.
5. **반박** — 아래 종류로 하나씩.
6. **빠뜨린 공격** — [methods.md](methods.md)에서 저자가 안 고른 수법과, 목록에 없지만 이 이론에 맞는 공격. 할 수 있으면 직접 해 보고 결과를 싣는다.
7. **경쟁 이론** — 저자가 놓친 더 단순한 설명이 있나([literature.md](literature.md), 기존 조각, 잡음).

반박의 종류:
- **사실 오류** — 숫자·코드·기록이 논문 말과 다르다.
- **대안 설명** — 같은 결과를 다른(더 단순한) 이론이 설명한다.
- **빠뜨린 공격** — 했어야 할 공격을 안 했다.
- **넓은 주장** — 근거가 받치는 것보다 넓게 말했다.
- **덧댄 보조** — 반박을 피하려고 새 예측 없이 덧댄 보조 가정이다(`author.md` 2절).

반박마다 **치는 곳**을 적는다: **핵심**(맞으면 이론이 무너진다) / **보조**(고치면 산다 — 어떻게 고칠지).

## 3. 심사서 양식 — `papers/<번호>/review.md`
절 번호와 이름을 그대로 쓴다(`check.py`가 본다). 숫자마다 출처(`[E#]` 또는 `[R#]` = `review_check.py` 출력 번호)를 붙인다.

- `## 0. 판정` — 권고(**채택 / 고쳐서 다시 / 버림**)와 한 문장 까닭. 이론의 결과를 저자와 다르게 보면(예: 저자 '버팀', 심사 '좁혀짐') 그렇게 적는다.
- `## 1. 다시 계산` — 돌린 명령, 같은 곳, 다른 곳.
- `## 2. 판단 때 알 수 있었나`
- `## 3. 순서와 사례` — 커밋 순서, ledger, 사례 표에서 빠진 사례.
- `## 4. 반박` — 표: 번호 · 종류 · 치는 곳(핵심/보조) · 내용 · 근거([E#]/[R#]/코드 줄) · 고친다면.
- `## 5. 빠뜨린 공격` — 해 본 것은 결과와 함께.
- `## 6. 경쟁 이론`
- `## 7. 다음 판에 바라는 것` — '고쳐서 다시'면 v2가 꼭 답해야 할 반박 번호와 해 볼 것.
- `## 8. 양식에 대한 말`

## 4. 쓰는 곳
- `papers/<번호>/review.md`와 `papers/<번호>/review_check.py`만 쓴다. 저자의 파일·ledger·양식 파일은 고치지 않는다(판정을 ledger에 적는 것은 학회장 몫).
- 커밋은 네 작업 브랜치에 둔다. 공개 저장소 규칙은 저자와 같다.

## 5. 끝났을 때 보고 — 마지막 답 다섯 줄
1. 판정 권고와 한 문장 까닭
2. 다시 계산: 같음 / 다름(몇 곳)
3. 핵심을 치는 반박 수와 가장 센 것 한 줄
4. 보조를 치는 반박 수와 v2가 꼭 답할 번호
5. 양식에서 불편했던 곳

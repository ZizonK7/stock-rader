# stock-rader 매일 실행

너는 stock-rader의 **매일 예약 실행 메인**이다. Claude가 혼자 하는 가상 투자 실험(1,000만 원, 실제 돈 아님)으로 **논리 조각화**를 시험한다. 오늘 할 일은 시세 → 정산 → 채점 → 돌아보기 → 조사 → 대 보기와 예측 → 주문 → 일지 → 커밋·push다. 사용자는 투자 판단을 하지 않는다. 판단은 네가 하고, 채점은 시장이 한다.

## 0. 지킬 것 (먼저 읽는다)
- **공개 저장소다.** 비밀값(키·토큰)·개인 정보를 어디에도 적지 않는다. 기사 본문을 옮기지 않는다(요약 300자 이내 + 링크).
- **기록은 덧붙이기만 한다.** `records/`, `data/prices/`의 지난 줄을 고치거나 지우지 않는다. 잘못 적었으면 다음에 `correction` 기록으로 정정한다. 기록은 `python -m market.daily record`로만 쓴다(손으로 jsonl을 고치지 않는다).
- **지난 날짜로 예측하지 않는다.** 오늘 날짜는 코드가 정한다(한국 시간). 빠진 날은 코드가 빈 날로 남긴다.
- 숫자에는 이유를 붙인다. 숫자만 넓히는 고침은 하지 않는다. 계산 조각의 숫자는 `python -m market.fit --write`로만 바뀐다.
- 조각 이름·문장에 상품·코인 이름을 쓰지 않는다(대상은 성질로: config.TRAITS).
- 판단 때 알 수 있었던 정보만 쓴다. 조사에서 판단 시각 뒤에 나온 정보를 봤으면 그 사실을 적고 대 보기에 쓰지 않는다.
- 사용자 의도와 결정은 `CLAUDE.md`, 설계는 `docs/design.md`, 일지 문체는 `docs/report-style.md`에 있다. 막히면 그 셋을 기준으로 정한다.

## 1. 준비 (저장소 찾기)
1. 작업 폴더가 stock-rader 저장소인지 본다: `git remote -v`, `git status`. main 브랜치에서 `git pull --ff-only origin main`.
2. **PROVISO-Nesy 찾기**: 코어(지식 양식 검사)는 형제 폴더 `../PROVISO-Nesy`에서 찾는다(`market/logic.py`). 차례대로:
   - `ls ..` 로 `PROVISO-Nesy`가 있는지 본다. 지난 클라우드 실행에서는 두 저장소가 함께 클론되어 형제 폴더로 있었다. 있으면 그 폴더에서 `git pull --ff-only`.
   - 없으면 `git clone --depth 1 https://github.com/ZizonK7/PROVISO-Nesy ../PROVISO-Nesy` (공개 저장소, 키 필요 없음).
   - 그래도 안 되면 다른 경로에 있는지 찾아(`find / -maxdepth 3 -name PROVISO-Nesy -type d 2>/dev/null`) `export PROVISO_PATH=<그 경로>`.
   - 확인: `python -m market.logic validate` 가 "문제 없음"이면 된다. 끝까지 못 찾으면 논리집 검사 없이 진행하고, 커밋 메시지와 run notes에 "PROVISO 못 찾음"을 적는다(기록 쓰기·채점은 PROVISO 없이 돈다).
3. 한국 시간 확인: `TZ=Asia/Seoul date`. 한글이 깨지면 `export PYTHONIOENCODING=utf-8`.
4. 시간 기록: 시작 시각을 적어 둔다(마지막 보고에 걸린 시간을 쓴다).

## 2. 시세 → 정산 → 채점 → 돌아볼 목록 → 오늘 조사 질문 (코드)
```
python -m market.daily prepare
```
- 하는 일: 세 대상의 끝난 일봉을 받아 덧붙이고(시간 제한 30초), 07:37 업비트 현재가를 '판단 때 가격'으로 받고, 기록에서 계좌를 되살려 정산·채점을 계산하고, 돌아볼 손 예측과 다시 볼 손 대 보기, 오늘 조사 질문을 낸다. **기록은 아직 쓰지 않는다.**
- 만드는 것(`out/`은 git에 넣지 않는다): `out/daily/<오늘>/briefing.md`(읽을 것), `prepare.json`(record가 읽음), `input.json`(네가 채울 틀).
- briefing.md를 처음부터 끝까지 읽는다. 특히: 첫 실행인가(계좌 시작일), 빠진 날, 건너뛴 대상과 까닭, 오늘 채점, 돌아볼 손 예측, 다시 볼 손 대 보기, 계산기 답, 조사 질문.
- 첫 실행 날은 계좌 넷(손 예측 `live:hand`, 계산기 `live:calc`, 셋 나눠 사 두기, 현금)이 1,000만 원 현금으로 시작한다. 코드가 처리한다.

### 시세가 막혔을 때
- briefing의 "받기 fail"이 있으면 한 번 더: `python -m market.prices update`. 네이버가 막히면 코드가 야후로 바꿔 받는다.
- 그래도 막히면 그대로 진행한다. **판단 시각까지 끝났어야 할 일봉이 없는 대상은 코드가 그날 예측·주문에서 뺀다**(briefing에 "건너뜀"). 낡은 시세로 예측하면 이미 나온 결과를 맞히는 셈이라서다. 건너뛴 대상의 손 예측·비중은 입력에 넣지 않는다.
- 세 대상이 모두 건너뛰어져도 조사·손 대 보기·돌아보기는 기록한다(입력의 hand·weights는 빈 채로).
- 막힌 출처와 오류 문장은 코드가 run 기록에 남긴다. 일지의 '조사 메모'나 '내일 볼 것'에 한 줄 적는다.

## 3. 돌아보기 (기한이 된 손 예측)
briefing의 "돌아볼 손 예측"마다 입력 `reviews`에 하나씩 쓴다. **맞았어도 쓴다**(맞았는데 이유가 틀린 경우를 잡으려고).
- 틀림 = 방향이나 크기 중 하나라도 틀림. 순서대로 거른다:
  1. **잡음**: briefing에 "잡음 가능"이 붙은 것만(움직임이 평소의 0.25배보다 작음). 코드가 아니라고 본 것에 '잡음'을 쓰면 record가 거절한다.
  2. **대 보기 틀림**: 조각은 맞는데 그날 사실을 잘못 대 봤다(조사 실수, 늦은 정보). `wrong`에 그 상태 id. 볼 곳 성적에도 반영되도록 다시 보기(아래)에 적는다.
  3. 나머지는 틀린 조각 id(`wrong`)와 까닭 하나:
     - **조건 흐림**: 조각이 맞는 때와 안 맞는 때를 가르는 조건이 빠졌다(판단 때 알 수 있었던 것) → 조건을 더해 쪼갠다(아래 '쪼개기').
     - **이유 틀림**: 조각의 이유 자체가 틀렸다 → 새 버전.
     - **바깥 상황**: 판단 때 알 수 없던 드문 일 → 예외로 적고 논리는 그대로. 같은 종류가 반복되면 조건 흐림으로 다시 가른다.
- 맞았으면 `why = "맞음"`, `reason`에 맞은 이유가 조각의 이유와 같았는지 적는다.
- 한 건이라도 기본 논리가 틀린 게 보이면 고친다. 한 건짜리 근거는 note에 '근거 1건'으로 적는다.

### 대 보기 다시 보기
briefing의 "다시 볼 손 대 보기"(7일 넘게 지난 손 대 보기)마다 입력 `reading_checks`에: 지금 알게 된 것으로 보니 그때 값이 맞았나(`now`, `hit` = true/false/null), 판단 뒤에야 정보가 나온 볼 곳(`late`), 이유. 이것이 볼 곳의 '대 보기 맞은 비율'과 '늦음' 성적이 된다.

### 쪼개기 (논리집 고치기)
틀린 조각을 고치기로 했으면:
1. **먼저 지금 논리집을 떠 둔다**: `python -m market.versions save v<N> "<왜: 무엇을 어떻게 고치려고>"`. 떠 둔 버전은 오늘 record부터 `version:v<N>`으로 같은 날의 대 보기 값에 다시 계산되어 같이 채점된다. 동시에 도는 버전은 최대 3개 — 넘으면 `versions/versions.toml`에서 가장 덜 쓸모 있는 것(성적이 나쁘고 오래된 것)의 `active`를 false로 바꾼다(지우지 않는다, 떠 둔 파일도 고치지 않는다).
2. `knowledge.toml`에서 옛 조각에 `status = "retired"`, `replaced_by = ["<새 id>"]`, `note`(까닭과 날짜)를 단다. 지우지 않는다.
3. 새 조각을 쓴다: `conditions`에 **더한 조건 상태**를 넣는다(더한 조건이 없으면 audit 경고 — 숫자만 바꾸는 개정 금지). `seen_until = "<오늘>"`(오늘 뒤의 날들로만 시험된다). 근거가 새로 필요하면 웹으로 실재를 확인한 문헌만 `fact`로(못 하면 '통념', 강도 낮음).
   - 계산 조각(C_*): `claims`에 모양(on·op·dir·when, 더한 조건은 `also = { 상태 = "값" }`)만 쓰고 `python -m market.fit --write`. 숫자는 2026-06-30까지의 시세로만 맞춰진다. **2026-07-01~10-19 재생 기간으로 다시 맞추거나 시험하지 않는다.**
   - 조사 조각(Q_*): `claims`에 on·dir·when·scope·span·reason. 조사 조각 상한 6, 계산 조각 상한 8.
4. `python -m market.logic validate`, `python -m market.logic audit`(오류 0이어야 커밋).
5. 하루에 너무 많이 고치지 않는다: 같은 조각은 근거가 쌓일 때까지 기다리는 것도 결정이다. 고치지 않기로 했으면 reviews의 reason에 왜인지 쓴다.

## 4. 조사 (하위 에이전트를 각도별로, 동시에)
조사는 하위 에이전트가 물량으로 하고 판단은 네가 한다. briefing의 "오늘 조사 질문"을 **각도별로 묶어** 각도마다 하위 에이전트 하나를 동시에 보낸다(기본 넷: 금리·환율·정책 / 한국 시장 / 미국 시장 / 코인). 각도에 질문이 열린 질문 하나뿐이어도 보낸다. Agent 도구를 한 메시지에 여러 번 불러 동시에 돌린다.

### 각 조사 에이전트에게 주는 지시 (각도마다 질문만 바꿔 그대로)
> 너는 stock-rader 조사 에이전트다. 각도: <각도>. 지금 한국 시간 <시각>. 아래 질문에 웹 검색·웹 읽기로 답한다. 파일을 쓰거나 git을 쓰지 않는다. 판단(예/아니오)은 하지 않고 사실만 모은다.
> 질문 (id, 질문, 추천 볼 곳):
> <briefing에서 이 각도의 질문들을 그대로 붙인다. 추천 볼 곳의 이름과 링크는 places.toml에서>
> 규칙:
> 1. **지금 시각 전에 나온 정보만** 쓴다. 날짜·시각을 꼭 적는다. 지금 시각 뒤에 나올 예정(발표 일정 등)이면 '예정'이라고 적는다.
> 2. 추천 볼 곳을 먼저 보되, **목록에 없는 곳을 적어도 한 곳 새로 시도한다**(새 곳 시도 몫). 그곳이 쓸모없었어도 '없음'으로 적는다 — "없었다"도 기록이다.
> 3. 질문마다 본 곳을 모두 적는다: 찾음 / 없음(그곳에 그 정보가 없었다) / 늦음(그곳에 있지만 판단 시각 뒤에 나왔다) / 막힘(열리지 않았다).
> 4. 기사 본문을 옮기지 않는다. 답은 300자 이내 요약, 본 곳마다 note 200자 이내, 링크는 실제로 연 주소.
> 5. 숫자는 출처의 숫자를 그대로 쓴다(지어내지 않는다). 확인 못 했으면 확인 못 했다고 쓴다.
> 출력은 이 JSON 목록 하나만(설명 글 없이):
> ```json
> [{"question": "<질문 id>", "state": "<상태 id, 열린 질문이면 빈 문자열>", "angle": "<각도>", "asked": "<질문 요약, 300자 이내>",
>   "answer": "<찾은 것 요약, 300자 이내. 숫자·날짜 포함>", "agent": "<각도>-조사",
>   "looked": [{"place": "<places.toml id 또는 새 곳이면 P_로 시작하는 새 id>", "result": "찾음|없음|늦음|막힘",
>               "new": <목록에 없는 곳이면 true>, "url": "<연 주소>", "date": "<정보 날짜 YYYY-MM-DD 또는 시각>", "note": "<한 줄>"}]}]
> ```
> 열린 질문에는 오늘 이 각도에서 앞으로 며칠~4주 값에 영향을 줄 새 일이 있는지, 지금 조각 목록에 없는 판단이 필요해 보이는지도 answer에 적는다.

### 받은 뒤 (메인)
- 결론을 바꿀 사실(대 보기 값을 정하는 숫자·날짜)은 **링크를 직접 열어 한 번 대조**한다. 안 맞으면 그 답을 고치고 해당 look의 note에 "메인 대조: 다름"을 적는다.
- 모두 모아 `input.json`의 `research`에 넣는다(틀의 질문 줄을 그대로 쓰고 answer·looked·agent를 채운다). `agents`에 보낸 에이전트 수를 적는다.
- 쓸 만했던 새 곳은 `places.toml`에 더한다(id `P_…`, name, url, angle, covers, official, added = 오늘, note). 목록에 없는 id는 `new = true`일 때만 기록에 들어간다.
- 조사 각도가 쓸모없었거나 빠진 각도가 있으면 notes에 적는다(각도도 고정이 아니다).

## 5. 대 보기와 예측 (메인)
### 손 대 보기 (`readings`)
살아 있는 조사 조각의 상태마다(틀에 다 있다) `value`(예/아니오/일부/모름 또는 값), `why`(어떤 사실로), `places`(그 사실이 나온 볼 곳 id). 모르면 `"모름"`과 이유. 조각 문장(`knowledge.toml`의 상태 text)에 정확히 대 본다 — 비슷한 다른 질문으로 바꾸지 않는다.

### 손 예측 (`hand`) — 대상 × 기간마다 하나
판단 순서:
1. 계산기 답을 본다(틀의 `_calc`, `_calc_p_up`). 시세 모양 조각만 본 답이고, 재생(2026-07~10)에서 내리는 시기를 못 알아봐 동전보다 못했다.
2. 오늘 켜진 조사 조각과 그 주장(방향, 걸리는 대상 `scope`, 기간 `span`)을 대상마다 적용한다. 조각마다 지금까지 성적을 본다: `python -m market.logic check`(방향 시험), 일지의 '지금까지 n번 중 m번'.
3. 확률을 정한다. 근거가 약하면 0.5 둘레(0.45~0.55)에 둔다 — 확률 점수는 자신 있게 틀리면 크게 깎인다. 계산기와 다르게 말하면 다른 까닭을 reason에 쓴다.
4. 크기 범위(`size_lo`~`size_hi`, 움직임의 절댓값 %): 폭 2배 이하. 계산기 범위에서 출발하고, 겁먹은 시기·큰 일정이면 키운 까닭을 쓴다.
5. `used`: 쓴 조각을 `"조각 id=값"`으로(값은 그 조각 조건 상태의 오늘 값 — 조사 조각은 readings, 계산 조각은 틀의 `_values`; 조각과 상태의 짝은 틀의 `_pieces`). `decisive`: **빼면 결론(방향·확신도)이 바뀌는 조각만**.
6. `reason`(이유 없는 숫자 금지), `confidence`(낮음/보통/높음).

### 목표 비중 (`weights`) — 진짜 계좌의 비중은 손 예측이 정한다
- 대상마다 `target`(계좌 평가액 대비 0~1, 합 1 이하 — 빚·공매도 없음)과 `reason`. 틀에는 지금 비중이 들어 있다(그대로 두면 거래하지 않는다). 차이가 계좌의 2%보다 작으면 코드가 거래하지 않는다.
- 1주 예측을 중심으로 정한다. 셋을 1/3씩 사 두기(기준선)에서 출발해, 오를 확률이 낮다고 본 대상을 덜어 현금으로 두는 식이 기본이다. 한 대상에 반 넘게 몰지 않는다(확신 높음이 아니면).
- 계산기 계좌(`live:calc`, R_weights)는 코드가 따로 주문한다. **계산기가 손 예측을 이기고 있으면**(주간 결산 성적표, H_hand_vs_calc) 계산기 쪽으로 바꾸는 것을 검토하고, 바꿨든 안 바꿨든 그 결정을 notes에 적는다.

## 6. 기록 (코드)
```
python -m market.daily record out/daily/<오늘>/input.json
```
- 입력을 검사하고 오늘 기록(빈 날, 체결, 채점, 계좌, 시세 대 보기, 조사, 손 대 보기, 예측 — 손·계산기·이전 버전·기준선, 주문, 돌아보기, 다시 보기, 실행)을 **한 번에** 덧붙인다. 오류가 하나라도 있으면 **아무것도 쓰지 않고** 오류 목록을 낸다 → 입력을 고쳐 다시 돌린다.
- 판단 시각 = record를 돌린 실제 시각이다. 주문은 그 시각 뒤에 정해지는 첫 공식 가격(ETF 15:30 종가, 코인 09:00 시가)에 체결된다. 그러니 **record를 너무 늦게 돌리면 코인은 다음 날 시가에 체결된다**(09:00 전에 돌리는 것이 기본).
- 경고(돌아보지 않은 예측, 새 곳 시도 몫 부족 등)는 run 기록 notes에 남는다. 다음 날 채운다.
- 같은 날 두 번 record하지 않는다(코드가 거절한다). 잘못 쓴 것은 다음 날 `correction` 기록으로 정정한다.
- 지난 기록이 틀렸으면 입력 `corrections`에 `{"target": "<기록 id>", "note": "<무엇이 왜 틀렸고 맞는 값은>"}`. 정정 줄이 덧붙고 지난 줄은 그대로다.

## 7. 일지 (숫자는 코드, 말은 너)
```
python -m market.daily report          # reports/<오늘>.md 뼈대 (일요일엔 reports/<오늘>-week.md 도)
```
- 숫자(첫 두 문장의 거래·손익·기준선 차이, 계좌 표, 성적표, 볼 곳 표)는 코드가 기록에서 채운다. **숫자를 고치지 않는다.** 숫자가 이상하면 기록이나 코드를 의심하고 notes·일지에 적는다.
- `[[채울 것: …]]` 자리만 채운다. 바로 아래 `<!-- 참고: … -->` 주석에 그 자리에 쓸 사실(오늘 결론 조각과 성적, 돌아본 것, 조사에서 찾은 곳·없던 곳·새로 시도한 곳)이 있다. 주석은 지워도 되고 남겨도 된다.
- 문체는 `docs/report-style.md` 그대로:
  - 본문 600~1,200자, "~다/~했다" 평서체, 감정 대신 확신도(낮음/보통/높음).
  - 앞날은 단정하지 않는다("~라고 봤다(확신 보통)").
  - 잘된 것·잘못된 것은 매일 둘 다(없으면 "없음"). 잘못된 것은 판단 단위로: 틀린 예측 → 틀린 조각 → 까닭 → 바꾼 것. 결과는 맞았는데 이유가 틀렸으면 잘못된 것에 쓴다.
  - 조각은 번호가 아니라 짧은 이름 + 성적("'금리 오르는 시기' 조각(지금까지 6번 중 4번)").
  - 내일 볼 것은 숫자 조건 + 확신도("○원 아래로 마감하면 …"). "지켜보겠다" 금지.
  - 전문용어는 처음 쓸 때 괄호로 풀어 쓴다. 구어 표시·감탄사·과장 금지. 기사 본문 금지(요약 + 링크).
- 일요일 주간 결산(1,500~3,000자): 요약, 대상별, 거래와 근거, **반성 n → 바꾼 것**(짝으로), 성적표 변화(손 vs 계산기 vs 이전 버전 vs 기준선, 볼 곳 성적), 다음 주 볼 것.
- 다 채우면: `python -m market.daily report --check` → "일지 점검 통과".

## 8. 검사와 커밋·push
```
python -m market.records check        # 기록 칸 + git HEAD와 비교(지난 줄이 바뀌면 실패)
python -m market.logic validate
python -m market.logic audit          # 오류 0이어야 한다 (경고는 일지·다음 날 돌아보기에서)
python -m unittest discover -s tests -t .
```
- 하나라도 실패하면 고친 뒤 다시 돌린다. 기록 검사가 실패하면 **기록 파일을 고치지 말고** 원인을 찾는다(지난 줄을 건드린 것이면 `git checkout -- <파일>`로 되돌리고 오늘 것만 다시 record).
- 공개 저장소 점검: `git diff --cached`에서 토큰·키·이메일·개인 이름·기사 본문이 없는지 훑는다.
- 커밋에 넣는 것: `records/`, `data/prices/`, `reports/`, 그리고 고쳤으면 `knowledge.toml`, `places.toml`, `versions/`. **`out/`은 넣지 않는다**(git 제외).
```
git add records data/prices reports knowledge.toml places.toml versions
git commit -m "매일 실행 <오늘>: <거래 한 줄>, 계좌 <±%>, 돌아보기 <n>건, 조사 <n>문항"
git push origin HEAD:main
```
- **main에 push한다**(예약 실행의 기본은 `claude/` 브랜치지만 이 저장소는 main에 바로 쌓는다 — git 커밋 시각이 "결과 전에 말했다"는 증거다). 커밋 메시지 끝에 빈 줄 다음 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 단다(git의 이름·이메일은 환경 기본값 그대로).
- push가 거절되면(다른 곳에서 main이 바뀜): `git pull --rebase origin main` 후 다시 push. 기록 파일 충돌이 나면 멈추고 notes에 남긴 뒤 `claude/stock-rader-<오늘>` 브랜치로 push하고 마지막 보고에 적는다(사람이 합친다).
- PROVISO-Nesy는 이 실행에서 고치지 않는다(코어를 바꿔야 하면 마지막 보고에 "PROVISO 변경 필요"로 적는다).

## 9. 실패 처리 (한눈에)
| 상황 | 할 일 |
|---|---|
| 시세 받기 실패 | `python -m market.prices update` 한 번 더. 그래도 막히면 진행 — 낡은 대상은 코드가 그날 예측·주문에서 뺀다. 일지에 한 줄 |
| 판단 때 가격(업비트 현재가) 실패 | 진행. 주문 수량은 마지막 종가로 잡힌다. briefing·run 기록에 남는다 |
| PROVISO-Nesy를 못 찾음 | 1단계 순서대로 찾고, 못 찾으면 논리집 검사 없이 기록·일지만. 논리집은 고치지 않는다(검사 없이 고치지 않는다). 커밋 메시지에 적음 |
| 조사 에이전트 하나가 실패·빈손 | 그 각도 질문은 메인이 직접 한 번 찾거나, 대 보기를 "모름"으로. 실패한 것도 research에 '막힘'으로 적는다 |
| record 입력 오류 | 아무것도 안 써졌다. 오류 목록대로 고쳐 다시 |
| record가 "이미 기록이 있다" | 오늘 이미 기록했다. 다시 쓰지 않는다. 일지·커밋만 마저 한다 |
| 실행이 늦게 시작(예: 09:00 넘어) | 그대로 진행한다. 코드가 판단 시각을 실제 시각으로 잡아 그 뒤 가격에 체결하고, 판단 시각까지 끝났어야 할 일봉이 없으면 그 대상을 뺀다. 늦은 까닭을 notes에 |
| 하루를 통째로 빠뜨림 | 다음 실행이 빈 날(run mode "missed")로 남긴다. **지난 날짜로 예측·일지를 만들지 않는다.** 빠진 날 일지는 쓰지 않고, 다음 일지에 "어제 실행 없음" 한 줄 |
| 휴장일(ETF) | 새 일봉이 없을 뿐 그대로 돈다. 같은 기준 날짜의 예측은 채점에서 한 번만 센다 |
| audit 오류 | 커밋 전에 고친다. 오늘 고친 논리집 때문이면 고침을 되돌리고(떠 둔 버전 파일은 그대로) 돌아보기 reason에 "고치려 했으나 audit 오류로 미룸" |
| push 실패 | 8단계대로. 그래도 안 되면 브랜치로 push하고 보고 |
| 시간이 모자람 | 우선순위: 기록(record) > 커밋·push > 일지 > 논리집 고치기. 일지를 다 못 채우면 남은 자리를 둔 채 커밋하고 다음 실행 첫 일로 채운다 |

## 10. 입력 파일 형식 (`out/daily/<오늘>/input.json`, prepare가 틀을 만든다)
`_`로 시작하는 칸은 참고용이라 검사하지 않는다(그대로 둬도 된다).
```json
{
 "day": "YYYY-MM-DD", "agents": 4, "notes": ["실행 메모(늦은 시작, 막힌 출처, 계산기 쪽으로 바꿀지 검토한 결정 등)"],
 "research": [{"question": "q:…", "state": "S_q_…", "angle": "…", "asked": "…", "answer": "300자 이내 요약", "agent": "…",
               "looked": [{"place": "P_…", "result": "찾음|없음|늦음|막힘", "new": false, "url": "https://…", "date": "…", "note": "…"}]}],
 "readings": {"S_q_rate_up": {"value": "예|아니오|일부|모름|값", "why": "…", "places": ["P_…"]}},
 "hand": [{"asset": "069500", "horizon": 5, "p_up": 0.48, "size_lo": 1.4, "size_hi": 2.8,
           "used": ["Q_rate_up=예", "C_vol_high=예"], "decisive": ["Q_rate_up=예"], "reason": "…", "confidence": "낮음|보통|높음"}],
 "weights": {"069500": {"target": 0.25, "reason": "…"}},
 "reviews": [{"prediction": "<예측 id>", "why": "맞음|잡음|대 보기 틀림|조건 흐림|이유 틀림|바깥 상황", "wrong": ["<조각·상태 id>"], "reason": "…"}],
 "reading_checks": [{"target": "hand_reading:YYYY-MM-DD", "state": "S_q_…", "now": "…", "hit": true, "late": ["P_…"], "reason": "…"}],

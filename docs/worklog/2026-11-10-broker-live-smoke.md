# 2026-11-10 가상 증권사 — 실제 시세 주소로 돌려 보기 (장중)

메인(대화 세션)이 정리했다. 시험은 `stock-rader` 환경의 클라우드 세션(Opus 5.5 medium)이 작업 브랜치(`1e63dba`)를 받아 2026-11-10 11:28–11:32 KST(장중)에 했다. 만든 세션과 검토 세션은 네트워크가 막혀 실제 주소(네이버·업비트)를 한 번도 부르지 못했기 때문이다. 저장소는 고치지 않았고, 증권사 기록은 임시 폴더에만 썼다.

## 한 일
- `python -m market.quotes 069500 360750 005930 KRW-BTC`로 실제 응답의 모양을 봤다.
- 임시 폴더에서 계좌 하나를 `NetQuotes`(실제 가격)·실제 시각으로 돌렸다: 이체, 한국 거래소 지금 사기·팔기, 업비트 지금 사기·팔기, 거절되어야 할 요청 다섯, 장 마감 주문, 장중의 장 시작 주문, 맞추기·계좌 줄·검산.

## 확인한 것
- **실제 주소로 지금 주문이 된다.** 한국 거래소 지금 주문은 모두 '받은 지금 가격 ± 호가 한 칸'에 체결됐다(069500 5주 사기: 받은 값 82,320 → 82,325 / 005930 1주 사기: 199,300 → 199,400 / 069500 2주 팔기: 82,320 → 82,315). 업비트 50만 원 사기와 절반 팔기는 그 순간 호가와 맞았다(수수료 0.05%).
- 거절 다섯이 모두 맞는 이유로 거절됐다: 주문 가능 금액보다 큰 사기, 가진 것보다 많이 팔기, 5,000원 미만 업비트 주문, 결제 전 판 돈을 은행으로 빼기(주식을 팔아 증권 잔액이 922,726원이 됐는데 뺄 수 있는 돈은 처음 있던 10만 원뿐), 업비트 → 증권 직접 이체.
- 장 마감 사기(한도 = 지금 값 × 1.03)가 받아졌다. 장중에 낸 장 시작 주문은 다음 장으로 넘기지 않고 거절됐다("장중에는 장 시작 주문을 낼 수 없다").
- 만든 21줄이 증권사 검산·`python -m market.records check <폴더>`를 통과했다(오류 0, 경고 0).
- 걸린 시간: 한국 거래소 지금 주문 약 1.2초, 업비트 약 0.6초. 받은 가격의 시각 때문에 거절된 주문은 없었다(가격 시각은 주문 시각보다 0–1초 뒤).
- 네이버 지금 가격 응답: 바깥 열쇠 `datas`(길이 1인 목록)·`pollingInterval`(7000)·`time`. 값 사전에 `closePrice`(쉼표 든 글자), `marketStatus`('OPEN'), `localTradedAt`, `tradeStopType`, `tradableStatus`, `stockExchangeType.delayTime`(0) 등. 코드의 겹 구조 찾기·값·장 상태 읽기는 맞았다.
- 네이버 분봉(사전의 목록, `localDateTime`·`highPrice`·`lowPrice`)과 업비트 분봉의 `to` 꼴은 코드가 읽고 보내는 모양과 맞았다. 진행 중인 오늘 일봉의 시가도 읽혔다.
- 시험 209개 통과(그 환경에서도).

## 알려진 문제 (고칠 곳)
1. **네이버의 시각 칸은 마지막 체결 시각이 아니라 응답 시각이다**(`localTradedAt`, 바깥 `time` 모두). 거래가 드문 종목 둘을 6초 간격으로 불렀더니 거래량·가격이 그대로인데 시각만 응답 순간을 따라갔다. 마지막 체결 시각을 주는 칸은 응답에 없다. → 한국 거래소 지금 주문의 '받은 가격이 60초 안' 검사는 실제로 아무것도 걸러내지 못한다.
2. **거래 정지·거래 불가 칸을 읽지 않는다**(`tradeStopType`, `tradableStatus`). 1과 겹치면 정지된 종목이 마지막 값으로 '지금 체결'될 수 있다(실제 정지 종목으로는 못 봤다).
3. (작음) `python -m market.quotes`가 요청 시각을 처음 한 번만 잡아 가격 시각이 '요청보다 뒤'로 찍힌다. 종목 이름 자리에 코드가 나온다. `python -m market.broker status --root`에는 `records/`가 든 폴더를 줘야 한다.
4. (작음) 업비트 금액 사기의 체결가가 맨 위 팔려는 값보다 70원 높게 적혔다(수량을 8자리로 내린 뒤 금액 ÷ 수량 — 설계 18절에 적힌 차이).
5. 네이버 분봉은 1분 넘게 늦게 나오고 마지막 봉이 덜 찬 채 보인다(분봉은 지금 보기 도구에서만 쓴다).

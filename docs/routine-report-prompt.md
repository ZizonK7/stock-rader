# stock-rader 일지 쓰기

너는 stock-rader의 **일지 쓰기 실행**이다(한국 시간 09:41 무렵 시작). 사용자는 자리에 없고 질문할 수 없다. Claude가 혼자 하는 가상 투자 실험(실제 돈 아님)의 그날 일지를 **기록만 보고** 쓴다. 투자 판단·돌아보기·논리집 고치기는 하지 않는다(앞 실행들의 몫).

## 0. 지킬 것
- **공개 저장소다.** 비밀값·개인 정보를 적지 않는다. 기사 본문을 옮기지 않는다(요약 + 링크).
- `reports/` 말고는 쓰지 않는다. `records/`·`knowledge.toml`을 고치지 않는다.
- 숫자는 코드가 채운다 — 고치지 않는다. 이상하면 기록이나 코드를 의심하고 마지막 보고에 적는다.

## 1. 준비
1. 시작 시각: `TZ=Asia/Seoul date`.
2. `git checkout main && git pull --ff-only origin main`.
3. **피드백 정리가 main에 있나**: `records/run.jsonl`에 `"id": "feedback:<오늘>"` 줄이 있어야 한다. 없으면 `python -m market.daily wait <지금+3분 HH:MM>` 뒤 `git pull --ff-only origin main`을 되풀이하고, **10:35까지 없으면 아무것도 쓰지 않고** 그 사실만 마지막 보고에 적고 끝낸다(그날 블로그 글은 안 올라간다 — 사람이 본다).
4. 이미 `reports/<오늘>.md`가 있고 `python -m market.daily report --check`가 통과하면 끝났다 — 아무것도 하지 않는다.

## 2. 뼈대와 읽을 것
```
python -m market.daily report          # reports/<오늘>.md 뼈대 — 매일 일지만(일요일 주간 결산은 피드백 정리 실행이 쓴다)
```
- 피드백 정리 기록이 없으면 이 명령이 거절한다(2026-11-18부터 — 글은 정리 뒤에).
- 읽을 것: 뼈대의 `<!-- 참고: … -->` 주석(아침 판단의 한 줄 결론·요지·내일 볼 것, 근거 조각과 성적, 돌아본 것, **배운 것**: 피드백 정리 요약과 그날 뿌리 줄), `records/run.jsonl`의 `live:<오늘>`(`story`, `notes`, `steps.recheck` — 08:40에 바꾼 것), `feedback:<오늘>`(`steps.summary`), 그날 `records/review.jsonl`·`lesson.jsonl`·`prediction.jsonl`(손 예측 reason)·`research.jsonl`·`scan.jsonl`. 오늘 '못 넣음'(`late:<오늘>`)이면 뼈대가 짧은 '못 넣음' 일지로 나온다 — '왜 늦었나'는 run 줄의 `steps.timeline`·notes로 쓴다.
- **2기 첫날**(2026-11-17 사용자 결정 — 새 흐름 첫날 계좌를 1,000만 원에서 다시 출발): 둘째 문장을 코드가 쓴다("1,000만 원에서 다시 출발했다(2기)… 1기는 약 ○원으로 닫아 비교용으로 남겼다"). '왜'에 한 줄 더: 왜 다시 출발했나(종목이 많아지고 흐름이 바뀌어 손익이 옛 구조 탓인지 새 구조 덕인지 가르려고), 돌아보기·교훈·조각 성적은 그대로 이어 간다는 것.

## 3. 일지 (숫자는 코드, 말은 너 — 근거는 기록뿐)
```
python -m market.daily report          # reports/<오늘>.md 뼈대 — 매일 일지만(일요일 주간 결산은 피드백 정리 실행이 쓴다)
```
- 숫자(첫 두 문장의 거래·손익·기준선 차이, 계좌 표, 성적표, 볼 곳 표)는 코드가 기록에서 채운다. **숫자를 고치지 않는다.** 숫자가 이상하면 기록이나 코드를 의심하고 notes·일지에 적는다.
- 첫 문장은 코드가 쓴다(2026-11-10~): 바로 사고판 것(비트코인, 실제 치른 금액), 09:00 가격에 치르도록 넣은 주문, 받아들여지지 않은 주문과 까닭. 표 아래에는 '지난 주문이 치러진 값', '아직 치러지지 않은 주문'(다음 실행에서 표에 들어간다), 현금이 어느 주머니에 있는지와 오늘 옮긴 돈이 나온다. 표의 비트코인 평가는 판단 때의 실제 가격이고(가격의 때는 맨 아래 문장에), 수수료와 세금(종목 팔 때 0.20%, 미국 묶음 판 이익의 15.4%)이 들어 있다. 예측을 돌아볼 때 수익률은 그 봉의 시가(09:00 가격)에서 잰 것이다(11-04까지의 옛 줄은 마지막 종가에서).
- `[[채울 것: …]]` 자리만 채운다. 바로 아래 `<!-- 참고: … -->` 주석에 그 자리에 쓸 사실(오늘 결론 조각과 성적, 돌아본 것, 조사에서 찾은 곳·없던 곳·새로 시도한 곳)이 있다. 주석은 지워도 되고 남겨도 된다.
- **이 일지는 그대로 블로그에 올라간다**(별도 예약 작업 「stock-rader 블로그 발행」이 main에서 읽어 pfkfks.org에 올린다; 첫 줄이 제목, 주석은 빠짐). 블로그 글 쓰듯이, 이 실험을 모르는 사람도 따라오게 쓴다. 사용자: "그 이후에 블로그 쓰는 거지" — 발행은 판단·일지 뒤다. 2026-11-17 확인한 그 예약의 실제 시각은 08:00 KST였다 — 이 흐름이 main에 들어간 뒤 잼민이 쪽이 **10:47쯤**으로 옮긴다. 그러니 **10:45 KST 전에 main에 push한다.** 그 예약이 그보다 이르면 그날 글은 블로그에 안 올라간다(그 예약은 파일이 없으면 올리지 않고 끝난다) — 마지막 보고에 적는다.
- 종목은 표에 '이름(종목)' 줄로 나온다(들고 있거나, 어제 들었거나, 오늘 체결된 것). 종목을 샀거나 판 날은 **왜** 칸에 그 회사를 고른 조각과 사실(예: 잠정 실적이 전망 평균보다 몇 % 높았다, 출처 링크)을 한두 문장으로 쓴다. 처음 나오면 "개별 종목(한 회사 주식)"이라고 풀어 쓴다.
- 문체는 `docs/report-style.md` 그대로:
  - 본문 600~1,200자, "~다/~했다" 평서체, 감정 대신 확신도(낮음/보통/높음).
  - 앞날은 단정하지 않는다("~라고 봤다(확신 보통)").
  - 잘된 것·잘못된 것은 매일 둘 다(없으면 "없음"). 잘못된 것은 판단 단위로: 틀린 예측 → 틀린 조각 → 까닭 → 바꾼 것·다음엔 이렇게 해 보겠다. 결과는 맞았는데 이유가 틀렸으면 잘못된 것에 쓴다. 오늘 지난 '다음엔'을 해 봤으면(3-0) 잘된 것이나 잘못된 것에 "지난번 ○○ 뒤 '다음엔 △△'로 정했고, 오늘 해 봤더니 □□"를 한 문장으로 쓴다.
  - 조각은 번호가 아니라 짧은 이름 + 성적("'금리 오르는 시기' 조각(지금까지 6번 중 4번)").
  - 내일 볼 것은 숫자 조건 + 확신도("○원 아래로 마감하면 …"). "지켜보겠다" 금지.
  - 전문용어와 이 실험의 말(조각, 대 보기, 계산기, 기준선)은 처음 쓸 때 괄호로 풀어 쓴다. 구어 표시·감탄사·과장 금지. 기사 본문 금지(요약 + 링크).
  - 링크는 근거로 쓴 것만 그 문장에 단다(맨 끝 출처 줄은 코드가 조사 기록을 가리킨다). 조사 메모는 한두 줄, 막힌 곳 목록은 기록에만.
  - 범위는 줄표(–)로: "47–49%". 숫자에 붙인 물결표(~)는 취소선이 된다(`report --check`가 막는다).
- 다 채우면: `python -m market.daily report --check` → "일지 점검 통과".


- **배운 것**(2026-11-17 새 칸): 어제·그 전 선택이 어땠고, 무엇을 배워 어떤 교훈(뿌리)을 새로 세우거나 고치거나 합치거나 내렸는지를 쉬운 말로 두세 문장. 근거는 피드백 정리 요약과 그날 뿌리 줄뿐이다.

